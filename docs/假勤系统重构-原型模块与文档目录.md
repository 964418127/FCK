> v2.12 变更：**审核规则页收敛为「只配假种自动 / 人工」；请假后果撤出原型**（2026-10-21）—— ① 删掉「一道申请怎么判」判定链路与「自动通过条件集」两块：前者是解释判定顺序的**说明性内容**（进文档 4.3），后者是未定义的细则（挂待决 8.20），都不该占原型；② 审核方式改为显式单选（自动 / 人工），**配置入口一眼可见**；③ **请假后果整页删除** —— 按「假勤只出事实结果」的边界，扣款归模块化薪酬、补缺归排班调度、通知归消息中心，假勤不配置后果；`AuditAndConsequence.vue`（两 Tab 容器）一并删除，路由直达审核规则页。

> v2.10 变更：**差异化从「多份方案」改为「一份方案 + 覆盖额度」**（2026-10-21）—— 上一版把每条差异化建成了独立方案（同假种多份、按 rank 挑一份），但业务的真实心智是：**基本规则都一样，唯一差异的就是额度** —— 如「事假统一 4 天，成都市 6 天」。改为：一个假种只有**一份方案**（周期 / 计量 / 结转等规则全公司一致），差异化是方案内的 `overrides` 条目 `{维度, 取值, 额度}`，命中的条目**只覆盖 amount 这一个数**；多条同时命中仍按维度 rank 取最具体的一条（对比开关保留）。取值多选不再折叠收起。连带：方案库一行一个假种，「差异化额度」以 chips 展示；抽屉下半段变成差异化条目编辑（加一条 = 选维度 → 选值 → 填额度）。
>
> v2.11 变更：**差异化收敛为「城市 / 门店」，岗位改为独立的「适用岗位」配置；统一额度改称「标准额度」**（2026-10-21）—— 岗位不是额度差异化的维度，而是「这份方案给哪些岗位用」的独立开关：方案 = **适用岗位**（哪些岗位有）+ **标准额度**（全公司打底值 + 规则）+ **差异化条目**（仅城市 / 门店，只改额度）。理由：岗位与地域是两种性质不同的轴 —— 岗位决定「有没有」，地域决定「值多少」；把岗位塞进差异化里，会出现「同一个岗位跨多城市该取哪条」的悖论。连带：岗位侧不再维护假种清单，改为只读展示方案勾选的结果；差异化示例补上「事假标准 4 天、成都市 6 天」；丧假不再对区域经理适用（演示适用岗位只决定有无）。

> v2.9 变更：**「适用范围」抽象成「差异化维度」**（2026-10-21）—— 上一版把差异写死成地域（全公司 / 城市 / 门店）不够用：公司自定义假同样要按岗位、职级、用工形式、司龄、合同主体分档。改为一张可枚举的**差异化维度表**：**全公司 · 合同主体 · 司龄段 · 职级 · 用工形式 · 岗位 · 城市 · 门店**（越靠右越具体），方案的 `scope` 由 `{ dimension, values }` 组成；解档按维度 rank **取最具体的一份**，仍是命中即停、不叠加。地域不再是特例，只是其中两项。连带：方案库改为**维度阶梯 + 员工画像预览**（挑一个真实员工，看他每个假种命中哪一档、哪些档被覆盖），并加「取最具体 / 取最优」的**对比开关**供讨论；盘点与移动端余额同样按画像解档。个人维度仍不支持（走「系统折算」）

> v2.8 变更：**额度方案引入「适用范围」，地域差异落到方案上**（2026-10-21）—— 此前 v2.6 说「地域差异改由假期方案按岗位引用表达」，**这判断是错的**：一个岗位横跨多城市（推拿师在深圳、成都都有人），岗位维度表达不了地域维度。改为：`假期额度方案` 每条带**适用范围**（全公司 / 城市 / 门店），同一假种可以同时存在多份；取值按 **门店 > 城市 > 全公司** 命中**最近的一份**生效，**不合并、不继承、不折算**；粒度到门店为止，**个人维度暂不支持**（要按人差异化走「系统折算」那一层）；**全部假种都可配范围**，不设白名单。连带调整：岗位声明由「引用哪些方案」退回为**「启用哪些假种」**（`quotaSchemeIds` → `quotaLeaveTypeIds`，岗位不该关心数值属地），数值在运行时按员工在职地址解析；方案库新增**生效预览**（选城市 / 门店看每个假种取哪份）与范围筛选；盘点 / 移动端余额改为按员工门店解析（陈伟·南山店 → 年假 10 天、婚假 5 天），并标记命中层级。示例链：年假 全公司 5 天 → 深圳 8 天 → 南山店 10 天

> v2.6 变更：**取消「城市 / 门店」配置下沉，改为统一配置 + 岗位声明**（2026-10-21）—— 假种字典去掉「配置下沉深度」（列、弹窗字段、统计项、继承说明全删）；假期审核规则由**三层继承（通用 → 城市 → 门店）**改为**全公司统一一层**，页面重做为「假种审核方式表 + 一道申请怎么判（假种 → 岗位 → 条件集 → 结论）+ 条件集 + 变更记录」；两条轴并存时**取严**（任一要求人工即人工，「按假种区分」的岗位不投票）。理由：下沉只声明了能力、只在一处兑现（审核规则），且没有城市 / 门店负责人角色，实质只是批量作用域；地域差异改由「假期方案按岗位引用」表达更便宜。同轮另一处收敛：**假种凭证要求改为枚举多选**（医疗证明 / 结婚证 / 亲属关系证明 / 死亡证明 / 出生医学证明 / 生育证明 / 其他凭证），不再接受自由文本，兜底走「其他凭证」由审核人判断

## 零、七个模型假设（预研提出，待评审确认）

| # | 模型 | 一句话 |
|---|---|---|
| M1 | **时间线占位与排他** | 以人为中心，事件按「是否排他」写在同一根时间轴上；排班与排假在同一段互斥 |
| M2 | **三层事实** | 计划（排班）/ 实际（打卡）/ 豁免（假）。计划 ≠ 实际即异常；岗位决定启用哪几层 |
| M3 | **名额 ≠ 额度** | 名额 = 组织容量（周期生成、共享、会被抢）；额度 = 个人可休量（私有、只减不增） |
| M4 | **配置双通道** | 人工配置（假种标准值 / 固定休息额度 / 审核规则）＋ 系统计算（临时假 ← 上月业绩、名额 ← 业务周期） |
| M5 | **统一配置 · 岗位声明 · 额度按维度分档** | 假种与审核规则全公司一套；差异由岗位声明（审批方式 / 补缺路径）表达；**额度 / 审核** 都是「一份标准 + 差异化条目」：额度 = 适用岗位（决定有没有）+ **三种计量之一**（周期发放 / 周期上限 / 按次上限）+ 差异化（仅城市 / 门店，只改数值）；审核 = 基础三项（凭证 / 提前期 / 审核方式）+ 差异化（仅城市 / 门店，条目默认继承基础值、改动哪项覆盖哪项），门店优先，**不做继承、不做叠加**，不建配置树 |
| M6 | **薪酬结构决定后果** | 订单驱动岗 → 只记时长、无扣款；固定＋绩效岗 → 按缺勤扣固定部分 |
| M7 | **事实流与判定结论** | 事实（时长 / 假种 / 起止）→ 时间线、薪酬、排班；结论（长假判定）→ 员工福利 |

## 一、交付原则：定义 / 配置 / 新建

> 本轮主要判断（预研口径，非定论）：**这次重构不是"全部设计新功能"**。相当一部分能力的所有者是现有系统或别组，我们只需**完成定义**，不必重画页面。同时，「能不能 100% 可配」的答案倾向于**不能，且不应追求**——配置必须分层。

### 1.1 三种交付形态

| 形态 | 我们的产出物 | 谁实现 | 是否建原型页面 |
|---|---|---|---|
| **① 定义层** | 语义定义、字段契约、边界说明、交互点 | 现有系统 / 别组 | **不建**（只进文档） |
| **② 配置层** | 配置页 + 配置项的判定顺序 | 我们（值由业务填） | 建，但只是"壳" |
| **③ 新建层** | 完整的页面与流程 | 我们 | 建，是真正的工作量 |

**定义层已确认的外部能力（不进原型清单）：**

| 能力 | 所有者 | 我们交付什么 | 我们不做什么 |
|---|---|---|---|
| 名额的生成与消耗 | **现有排班排假系统** | 名额的语义（组织容量 / 周期 / 共享）；与假勤的交互点（申请时校验）；对外字段（当前值 / 已用 / 剩余） | 不重写生成器、不重画容量台 |
| 临时假小时数折算 | **现有额度模块** | 输出契约（字段、冻结时点、口径）；额度账户的"来源可解释"展示 | 不重写业绩折算公式 |
| 打卡与出勤事实 | **打卡组** | 需要的字段与口径（原始时刻 vs 有效/无效） | 不做打卡规则引擎 |
| 时间线占位与冲突 | **人事组** | 写入的事件结构、读取的冲突返回 | 不做时间线本身 |

### 1.2 可配置度阶梯（关键判据：**配置只能作用于「值」，不能作用于「逻辑」**）

| 层级 | 可配置度 | 内容 | 说明 |
|---|---|---|---|
| **L0 领域模型** | 0%，写死 | 排他占位、名额 ≠ 额度、三层事实 | 若这些可配，系统将不可解释 |
| **L1 算法逻辑** | 仅参数可配 | 业绩折算（权重 / 上限 / 快照时点）、名额生成（周期 / 容量基准） | 算法有 owner；**参数面很可能在对方系统里配**，我们只写定义 |
| **L2 业务规则** | 可配置 | 假期类型、额度标准值 + 差异化、审核要求（凭证 / 提前期 / 审核方式）+ 差异化 | 我们建配置页，业务填值 |
| **L3 展示偏好** | 完全开放 | 列表列、筛选项、看板维度 | 用户级偏好，非业务规则 |

**为什么不能 100% 可配**：每增加一个配置维度，组合数相乘（假种 × 岗位 × 薪酬结构 × 审核条件 × 周期……），很快没有人能回答"**这个员工为什么走了人工**"——而这恰是业务最常问的问题。本轮据此砍掉了「城市 / 门店**层级树**」：假种与审核规则全公司一套，差异只由岗位声明表达，两条轴并存时**取严**（任一要求人工即人工），把"假种 × 层级"的矩阵直接消掉。

**保留的例外（v2.8 → v2.14）**：**额度的数值**与**审核要求**允许按**城市 / 门店**分档，因为这是业务硬需求（深圳社保与招聘口径确实高于其他城市、南山店独立承诺 10 天年假、成都事假额度上浮、南山店旺季年假转人工），且它是**值**不是**规则** —— 命中即停，不继承、不叠加、不折算。二者的区别要写清：**继承树是「规则叠加」，差异化是「按在职地取一个数」**；前者会让"为什么"不可解释，后者只要问清「你在哪个店」就能解释。
**岗位不进差异化**：岗位与地域是两种轴 —— 岗位决定「有没有」（方案的**适用岗位**），地域决定「值多少」（**差异化条目**）。把岗位塞进差异化，会遇到「同一岗位横跨多城市取哪条」的悖论，也会让岗位页与方案页互相打架。职级 / 用工形式 / 司龄 / 合同主体本轮同样不做差异化（要按人差异化走「系统折算」），列为待决 8.19。

| # | 能力 | 实现方 | 可改性 | 我们需要确认 |
|---|---|---|---|---|
| C1 | 名额生成与消耗 | 现有排班排假系统 | 待确认（可加字段/接口？） | 能否返回"已用/剩余"而非仅"名额" |
| C2 | 临时假小时折算 | 现有额度模块 | 待确认 | 输出字段与冻结时点 |
| C3 | 打卡记录 | 打卡组 | 待确认 | 原始时刻 vs 有效性判定 |

- 4.1 假种规则表（是否排他 / 启用 / 短备注 / 适用性 / 额度来源；**带薪与扣款口径归模块化薪酬**；**有没有额度由额度方案决定**；**单位与数值都在额度方案**）
- 4.2 额度规则（固定 ＋ 业绩折算公式与可解释性；**标明算法归属**）；含**适用岗位**（哪些岗位有）与**差异化规则**（仅城市 / 门店、门店优先、多条命中取一条）；个人维度不支持
- 4.2.1 **三种计量方式**（值全部只在「假期额度方案」一层，无岗位额度层）：
  - **周期发放**：每周期预发固定额度给员工，周期内可用、可结转（由方案声明），如年假 10 天/自然年、班次假 4 天/自然月
  - **周期上限**：不预发，按实际获取计量、周期内封顶；系统折算假种（临时假）用此形态，历史已折算的存量不在本系统处理
  - **按次上限**：不预发、不占周期余额，每次申请封顶 + 有效期（如婚假 ≤3 天/次、领证后 12 个月内）
- 4.3 审核规则（**每假种一份：凭证要求 + 提前申请期 + 自动 / 人工**；三条基础配置 + 城市 / 门店差异化（差异化条目默认继承基础值、改动哪项覆盖哪项）+ 与岗位审批方式取严 + 判定顺序；条件集待定）
- 4.4 事实结果的三个出口（薪酬 / 排班调度 / 消息）—— 假勤不配后果，只保证事实可被消费
- 4.5 名额规则（周期 / 生成 / 调整；**标明实现方为现有排班排假系统**）

- 8.20 **自动通过的条件集要不要做**（如「≤1 天且非旺季」才自动；本轮只有假种级自动 / 人工，没有条件粒度 —— 归属：假勤 × 业务，卡在「条件由谁维护、是否按假种差异化」）
- 8.19 **职级 / 用工形式 / 司龄 / 合同主体是否也要做额度差异化**（本轮按「只做城市 / 门店」收敛；若要做，是先扩差异化维度，还是并进「系统折算」的按人调整 —— 归属：假勤 × 薪酬）
- 8.21 **考勤组的打卡方式 / 有效范围由谁维护**（打卡组的资产，原型里在假勤侧可编辑，按「只做定义」的口径其实只该引用 —— 归属：打卡组；卡在「有配置接口可写回」还是「只能只读同步」）
- 8.22 **补缺方式（同岗位补 / 不补）算假勤声明还是排班策略**（现写在岗位假勤方案里，假勤实际只输出「缺岗信号」；若排班侧已有该策略，此处应退为只读展示 —— 归属：排班调度）
