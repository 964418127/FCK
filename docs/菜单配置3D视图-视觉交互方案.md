## 一、一句话

把菜单配置从「勾选清单」变成一条可以走、可以拖的**菜单街区**：分组是轨道，菜单项是轨道上的方块，横向代表组内顺序、纵深代表分组顺序；**点方块切换显隐，拖方块/拖轨道调整顺序**。

---

## 二、判断：3D 解决什么，不解决什么

先把话说清楚，避免为了 3D 而 3D。

**3D 真正带来的价值**

1. **顺序变成可感知的东西**。现在 48 个菜单项的先后只存在于代码里，页面上没有任何一处能看出「假勤管理 排第几、组内谁在前」。3D 把顺序摊成一个可看的空间。
2. **拖拽即结果**。改顺序不再需要「上移 / 下移」按钮点十几次，也不需要改代码重跑。
3. **整屏总览**。一屏看到「哪些组很长、哪些项被藏起来了」，这是列表视图做不到的（列表要滚）。

**3D 不适合的事（必须承认）**

- 批量勾选：要一次隐藏 20 项，列表的 checkbox 比 3D 快得多。
- 精确落位：3D 拖到「第 5 位还是第 6 位」永远不如一条线性顺序条确定。
- 小屏 / 触屏：单指拖块与页面滚动天然冲突。

**结论**：**3D 是主视图，列表视图必须保留**（右上角一键切换，记忆上次选择）。3D 里能做的事列表都能做；列表是兜底，也是精修入口。这不是妥协，是这类操作型配置页的合理分工。

## 三、空间编码（坐标系怎么用）

| 轴 | 含义 | 交互 |
| --- | --- | --- |
| **X（横向）** | 组内顺序，从左到右 = 从上到下 | 拖方块左右 = 改组内位置 |
| **Z（纵深）** | 分组顺序，越靠前 = 越靠近用户 | 拖整条轨道 = 改分组位置 |
| **Y（高度）** | 可见性 | 可见 = 立着的实体方块；隐藏 = 只剩虚线线框的空壳 |
| 颜色 |  交互态 | 主色 `#A40035` 描边 = 选中 / 拖拽中 |

**为什么用「街区」而不是别的**

- 不用环形旋转木马：环形适合「无序的并列」，而菜单顺序是有前后语义的，环上没有起点。
- 不用立体树：树只表达包含关系，表达不了「第几个」。
- 街区形态里，顺序是一条可拖的直线，层级是纵深分层 —— 两个维度各司其职，不会互相打架。

## 四、视觉规格

| 项 | 规格 |
| --- | --- |
| 底色 / 地面 | `#FBFAF9` / `#F4F1EE`（描边 `#E4DFDA`） |
| 方块 | 面 `#FFFFFF`、顶面 `#FAF8F6`、侧面 `#F0EBE7`、描边 `#DED8D3` 0.5px |
| 隐藏态 | 仅线框，`#C4BDB8`，虚线 3/3，文字 55% 透明 |
| 交互态 | 主色 `#A40035` 1px 描边 + 极浅底 `#FFF7F8`，不加发光 |
| 文字 | 方块主名 `#2B2724`，计数 `#8A827E` |
| 相机 | **正交相机**（不用透视，避免远处方块变形），45° 俯角等距，默认 viewSize 6 |
| 视角预设 | 等距 / 俯视 / 正视 / 纠偏（把倾斜相机拉回水平） |
| 方块尺寸 | 1.0 × 0.62 × 0.14（世界单位），槽距 1.12，组带高 0.06 |
| 光照 | 半球光 + 单向平行光，**不开阴影**；用方块侧面深一档代替投影 |
| 动效 | 悬停上浮 0.04 / 0.12s；让位 0.15s ease-out；落位 0.18s；切页签淡入 0.25s |
| 字体 | 方块表面用 canvas 贴图（中文 4–5 字，256×160 画布）；浮签用 CSS2D，保证文字清晰 |

原则：**只用实体/线框区分可见性，只用主色描边表达交互，不做任何装饰性光影**。3D 场景越素，越像工具而不是玩具。

## 五、交互规格

| 动作 | 触发 | 反馈 | 是否落库 |
| --- | --- | --- | --- |
| 旋转视角 | 左键空白处拖动 / 滚轮缩放 | 相机环绕，不触发任何数据变化 | 否 |
| 悬停 | 指针移入方块 | 描边亮起 + 浮签（名称 / 路由 / 顺序 i/n） | 否 |
| 切换显隐 | **单击方块** / 键盘空格 | 方块 ↔ 线框 0.16s 过渡，顶部计数变化 | 是（`hidden`，立即） |
| 组内排序 | 拖方块左右 | 浮起 0.06、相邻方块让位、虚线槽位预示落点 | 是（落位时 `order`） |
| 跨组移动 | 拖方块纵深移动到别的轨道 | 目标轨道整条高亮 + 插入位标出 | **本版不做**，见待决 6 |
| 分组排序 | 拖整条轨道（或左侧分组名）上下 | 轨道滑动，其余轨道让位 | 是（`order`） |
| 聚焦分组 | 点左侧分组名 | 相机飞到该轨道，其余 0.35 透明 | 否 |
| 搜索 | 顶部输入 | 命中项高亮、其余降暗，相机居中第一个命中 | 否 |
| 撤销 | `Ctrl/⌘ + Z` | 回退最近一次 `hidden`/`order` 变更并落库 | 是 |
| 视图切换 | 右上「3D / 列表」 | 双视图互切，选择记在 localStorage | 否 |

**拖拽的判定细节**

- 按下后位移 **< 6px 视为点击**（切换显隐），不进拖拽 —— 防止「想点击却旋转了视角」。
- 进入拖拽即**锁定相机**，松手 200ms 后才恢复，避免手抖带动视角。
- 拖拽全程只在本地改顺序，**松手才提交**；`Esc` 中途取消，回原位，不发请求。
- 让位用「最近槽位中心距离 < 0.5 槽距」判定，不做自由落点。

**键盘与无障碍**

画布 `tabindex=0`，方向键在方块间移动，空格切换显隐，`Alt + ↑/↓` 调序，`Esc` 取消拖拽。所有 3D 操作在列表视图都有等价入口 —— 这是硬要求，否则 3D 就成了门槛。

## 六、页面结构

自上而下四层：

1. **页头**：标题 + 「服务端共享/仅本机」标签 + 更新时间 + 右上「3D / 列表」分段控件。
2. **页签**：Web 端 / 移动端 / 文档中心（沿用现有三页签与 `已显示/总数` 徽标）。
3. **主区**：左侧 3D 画布（占满），右侧 232px 检查器 —— 选中项的名称、所属分组、顺序、路由，以及「上移 / 下移 / 隐藏 / 移到分组」四个按钮。
4. **底部顺序条**：一条 2D 线性 strip，`1 假期盘点 · 2 出勤方案 · 3 …`，可直接点击定位，也可拖拽精排。**这是 3D 的确定性兜底**：3D 里调完，顺序条里能一眼核对。

画布内浮层只保留三样：左上计数（可见 n / 隐藏 m）、右上视角预设、左下操作提示一行。**不在画布上加任何说明性长文案**。

## 七、排序的数据与接口

### 7.1 状态结构

`hidden` 继续存「隐藏了什么」，新增每个端一份**扁平顺序表**（不嵌套，避免父子结构各存一份导致失配）：

```json
{
  "hidden": ["leave-wm-quota"],
  "order": {
    "web":    ["welcome", "docs", "data-validation", "monthly-diff-confirm", "..."],
    "mobile": ["m-g-duty", "m-store-hanging", "..."],
    "doc":    ["doc-product-v2-phase1", "..."]
  }
}
```

### 7.2 合并规则（关键：对新增/删除菜单要稳）

1. 节点位置 `pos(id) = order[tab].indexOf(id)`，取不到返回 `Infinity`。
2. 同一父级下按 `(pos, 原始下标)` 升序排 —— **没进过 order 的新菜单自动落到该组末尾**，不会插到别人前面，也不会因为服务端没记录而消失。
3. `order` 里已不存在的 id 渲染时忽略，下次提交时顺手清掉。
4. **老的 `{hidden}` 状态天然兼容**：`order` 缺省 = 全按原始顺序，行为和现在完全一致。

### 7.3 接口改造

服务端 `scripts/gate-store.js`：`POST /api/gate` 的 body 从 `{hidden}` 扩为 `{hidden, order}`，`order` 可选（缺省则保留原值，不整体清空）。SSE 广播体同步带上 `order`。客户端 `useGateConfig.js` 新增：

- `gateState.order`（`{web, mobile, doc}`）
- `orderedNodes(tab)` —— 按 7.2 规则返回排好序的树，供渲染
- `moveNode(tab, id, parentId, index)` / `moveGroup(tab, id, index)` —— 本地即时生效 → 防抖提交
- `undo()` —— 保留最近 20 步快照（仅内存）

并发语义仍是「整体覆盖、后写获胜」。排序是低频人工操作，**暂不引入 per-item patch**；但提交前比对一次 `updatedAt`，变了就提示「有人刚改过，已按最新顺序合并」——待决 3。

## 八、硬前提：侧边栏必须先变成数据驱动

这是本方案里工作量最大、也最容易被忽略的一块。

**现状**：`src/components/MainLayout.vue` 的侧边栏是**手写模板**，48 个 `el-menu-item` / `el-sub-menu` 各自带 `v-if="visible(id)"`（`menuCatalog.js` 反而是从这份模板反向生成的）。模板里没有 `v-for`，因此**顺序写死在 HTML 里，排序配置没有任何地方可以生效**。

**所以排序功能的前置条件是**：

1. 新建 `src/config/sidebarMenu.js` 作为唯一数据源：`{ index, label, icon, to, children }`，图标存组件引用。
2. `MainLayout.vue` 改为递归渲染这份数据（`SidebarNode` 组件），并消费 `orderedNodes('web')`。
3. `menuCatalog.js` 由同一份数据派生，`npm run gen:menu` 退役 —— **顺带消掉「模板与目录两份真相」这个隐患**。
4. 迁移验证：用脚本从现有模板抽取 id / label / icon / 顺序，与 `menuCatalog` 对账（id 集合必须完全一致）；迁移后逐组比对渲染结果。

**搬完之后顺序才有意义**。移动端（`mobileMenuGroups` 已被 `MobileMenu.vue` 用 `v-for` 渲染）和文档中心（`docMenu` 已数据驱动）**不需要这一步**，只有 Web 侧边栏要动。

如果这一块不做，3D 视图就只是一个「能看不能改顺序的模型」，方案价值折半。**是否接受这项改造，是最需要先确认的一件事。**

## 九、技术实现要点

| 项 | 做法 |
| --- | --- |
| 依赖 | 仅新增 `three`；`OrbitControls` / `CSS2DRenderer` 从 `three/examples/jsm/` 取，不引额外库 |
| 体积 | 3D 模块用**动态 import**，只在 `/gate` 且切到 3D 视图时加载，独立 chunk，不进首屏 |
| 相机 | `OrthographicCamera`，按容器宽高比算 frustum；`OrbitControls` 限 `polarAngle` 20°–80°、禁平移越界 |
| 场景 | 组带 `PlaneGeometry`；方块 `BoxGeometry` + canvas 文字贴图（中文用系统字体绘制，避免加载字体文件） |
| 拾取 | `Raycaster` + `pointermove` 节流 16ms；`pointerdown → 阈值判定 → 拖拽` 三段式 |
| 补间 | 自写 rAF lerp（约 40 行），不引 tween 库 |
| 性能 | 单页最多约 60 个方块，量级极小；`pixelRatio` 上限 2；组件不可见 / 页面切走时 `setAnimationLoop(null)` |
| 销毁 | `onBeforeUnmount` 里 dispose geometry / material / texture，移除 canvas 与监听 |
| 降级 | WebGL 不可用 → 直接渲染列表视图 + 一行提示，不做半残的 3D |
| 触屏 | 单指拖块、双指旋转；窄屏（< 900px）默认直接进列表视图 |

### v0.3 修订（2026-10-21 下午，试用反馈修复）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 分组的显隐性没有被控制 | 3D 里分组牌只有「拖动排序」，既不显示整组显隐状态，也无法切换；三级分组的中间层同理 | 分组牌按自身 hidden 渲染成空壳、所在轨道压暗；**单击分组牌 = 整组显隐**（含全部子项，与列表勾选同一套语义），拖动阈值放宽到 8px 减少误触；三级分组的中间层卡牌单击也按整棵子树开关 |
| 拖动排序后页面像被重置刷新 | 每次模型变化都**全量重建场景**并 `applyView` 复位相机，视角、缩放全部跳回预设 | 改为**增量同步**：节点增删才动场景，只换位置走缓动（约 0.2s 滑入落位）；相机朝向与缩放全程不动；换页签或结构变化时只重算取景范围。另在「3D ↔ 列表」切换时保留视角 |

**回归数据（无头浏览器）**：相机稳定对照噪声 0.05px，拖卡牌后视角漂移 0.01px（修复前每次拖拽整场景重建 + 相机复位）；分组单击 → `hidden` 提交整组 id → 侧边栏整组消失；HUD 显示「N 组整体隐藏」。顺带修复：「撤销」按钮的 disabled 读的是非响应式的 `canUndo()`，状态变化后不刷新，改为 `gateState.undoDepth`。

### v0.4 修订（2026-10-21，移动端页签看不到功能入口）

**现象**：3D 切到「移动端」页签只有一条轨道 + 6 张分组卡牌，分组下的功能入口完全没有渲染。

**根因**：3D 只画两层（分组=轨道、功能入口=卡牌），而移动端树是三级——顶层有一个纯包装根「移动端菜单」（`mobile-root`），3D 把它当成唯一轨道、把 6 个分组当成卡牌，真正的格子（第三层）根本不在场景里。

**修复**：`GateConfig.vue` 新增 `drillRoot()`——单一根且子节点还带子节点（纯包装层）时自动下钻一层再交给 3D。下钻后移动端 = 6 条轨道（职能岗位/推拿师/客户经理/总部岗位/请假模块/离职模块）+ 各组格子卡牌；分组排序、整组显隐、格子拖拽全部沿用原有语义。列表视图保持三级层级不变（根的勾选框仍可一键整块开关移动端）。文档中心是多根结构，不受影响。
