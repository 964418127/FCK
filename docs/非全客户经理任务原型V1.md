# 非全客户经理任务原型 V1

> 全局业务流程、任务来源、定时发布规则和功能模块说明以文档中心的“非全客户经理”入口及“功能模块”章节为准。本文保留原型交互和实现边界。

## 入口

- Web：`/parttime-task-management`，菜单“非全客户经理 / 排班排假”。
- Web 任务跟踪：`/parttime-task-tracking`，独立菜单“非全客户经理 / 任务跟踪”。按日期、门店、人员、任务状态与异常打卡筛选，展示计划时段、实际到店和离店时间（记录到秒）、实际在店时长。无记录的历史任务显示“未记录”。
- 移动端：`/mobile-parttime-tasks`，我的任务与可选任务。
- 通知：`/mobile-notification`，发布通知进入可选任务，临时派单通知进入我的任务。
- 考勤：`/mobile-account-manager-attendance?mode=parttime`，读取当前人员当天未取消的任务。

## 业务范围

统一按门店、每周各日、起止时段和名额配置需求，备注用于运营说明，不区分长期、短期类型。结束日期选填，也可在不再需要时直接删除某天的时段。不使用推拿师的 A/B 类或最低每日工时规则。

每周四上午 10:00 将有效配置展开成具体日期的可选任务。发布后按任务快照保留时段与名额，后续修改、停用或删除配置影响未来发布，已发布任务及已选任务保持原安排。备注不参与选取资格或任务发布筛选。每周期只发布一次。手动发布允许提前演示。

选取成功即进入“待到店”，不经过“待接受”。校验签约商圈、剩余名额、时段重叠、跨店通勤缓冲、单日累计工时和服务门店数。

取消任务后，原任务保留为“已取消”，产生一条待补人需求，原名额为接替人员保留。约 1 秒后尝试安排其他符合条件的人员；成功时展示接替人员任务通知，当前人员列表不会新增该任务。暂无合适人员时留在 Web 临时补人列表继续处理。

全职请假按实际缺岗时段生成临时需求，每段不超过 4 小时。例如 10:00–22:00 拆为 10:00–14:00、14:00–18:00、18:00–22:00，接替人员分别校验每日工时。原任务人员、来源及接替结果仅 Web 展示。

Web“临时补人”为直接发布临时任务的运营入口，填写门店、日期、时段、需求人数和备注，不要求请假人员或原班次。发布后自动派发，展示需求人数、已派人数和具体人员。人员不足时保留待派发或部分派发状态，可重试派发；已派出的任务进入各人员的任务列表与任务跟踪。手动发布立即生效，不等待周四周期发布。

全职请假与非全取消任务通过业务事件自动产生并派发临时任务，保持各自的来源记录。

## 本版采用的待确认口径

- “下周六至下下周五”按自然周理解：2026-10-01 周四发布 2026-10-10 至 2026-10-16 的任务。
- 每段最多 4 小时，同时沿用现有业务文档的每人单日累计最多 4 小时。
- 跨门店通勤缓冲暂为 30 分钟；后续可接门店间隔时间库。
- 运营可通过备注描述需求用途，选取资格不依据“长期／短期”等文字判断，不增加优先选取权或固定人员绑定。
- 同一门店在重叠生效日期内，不允许配置重叠时段，避免重复需求。

## 原型边界

数据在浏览器 localStorage 持久化，同源标签页同步。发布检查在页面加载及任务页面运行期间执行，关闭浏览器后不会运行后台调度。请假事件处理支持自动拆分和派发，尚未接入真实全职请假审批。

真实系统需由后端负责周四定时发布、多人抢占名额的事务控制、任务和通知的角色权限、请假审批事件，以及可靠的补人调度。当前转发任务池仍沿用既有原型行为，30 分钟回退尚未接入后台计时。

## 验证

`node --test tests/parttimeTasks.test.js`：发布日期与周期、有效期、重复发布、名额占用、工时、通勤、取消接替、请假拆分、配置校验、发布快照、删除时段、旧数据迁移，以及不支持 `crypto.randomUUID()` 的环境。

## 非全客户经理收入保底

Web 菜单统一为“任务需求”，独立“收入保底”页面统一管理通用、城市和门店配置。通用保底固定在顶部一行展示金额和编辑入口；左侧选择城市，右侧直接展示对应保底标准和该城市门店列表，无折叠交互和结算试算。

- 通用保底只配置一个金额，单位为元/月，适用于未新增城市配置的城市。
- 城市通过新增配置维护一个月保底值，覆盖通用值。左侧仅列已新增的城市，不预先生成城市配置。
- 门店通过新增配置维护一个非负差异额。最终月保底 = 城市保底（未配置城市时为通用值）+ 门店差异额。
- 门店不需要差异额时直接删除配置，回到城市保底。删除城市配置时同时删除其门店配置，回到通用保底，操作前显示确认提示。
- 页面不再设置计价方式、生效月份、收入统计、档位和筛选条件，也不提供结算试算。按周结薪、月末保底补差仍是薪酬业务要求，未接入实际发薪。

金额均为演示值。旧版配置迁移为当前月对应的城市月额及已匹配门店档位的月增加额，旧存储保留。通用保底默认 2000 元/月，预置成都 2400、杭州 2600、北京 2800 元/月及四家门店差异额；城市可选成都、杭州、北京、南京、重庆、宁波、西安，各城市提供演示门店。默认示例仅补充一次，保留已有金额，删除后刷新不会重新补回。新增演示门店只用于保底配置，不影响原有任务门店。

`node --test tests/parttimeGuarantee.test.js`：通用继承、城市覆盖、门店增加额、删除后回退、零值与非法金额、旧版迁移。

## 非全客户经理单价配置

新增独立“单价配置”页面，维护新客、评价、客次三项单价。顶部通用配置提供默认价；城市、门店和个人都可逐项覆盖。个人配置的键为“客户经理工号对应 ID + 门店 ID”，同一人在不同门店可分别配置。每项依次采用个人在该门店的单价、门店单价、城市单价、通用单价；0 元为有效覆盖值。旧版已保存的城市、门店和个人价会保留，缺少通用价的旧数据补入演示默认值。

页面采用城市、门店、客户经理三列独立布局。城市和门店分别可新增配置，无需先选择上一级；个人价可直接选择客户经理和门店新增，不要求已有城市或门店单价。每列分别支持城市名、门店名或编号及城市、姓名或工号搜索。个人列按人员汇总其所有已配置门店，逐项显示生效价格及来源。

每个单价明确标注“本级配置”或“继承通用／继承城市／继承门店”；编辑弹窗对未单独配置的项目展示实际继承金额及来源。

新增门店单价时，弹窗先选城市，再从该城市的门店中选择；该筛选不影响三列的独立浏览与新增个人价。

演示数据包含杨小雪在兴隆湖店和麓山店的不同个人价。页面配置保存在 localStorage；个人与门店的关系在新增个人价时建立，尚未接入正式人事关系及薪酬结算。`node --test tests/parttimeUnitPrices.test.js` 覆盖逐项继承、跨门店独立、零值、删除回退及无效数据。
